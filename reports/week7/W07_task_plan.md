## 4. 技术文档

`reports/week7/技术文档.md` 分成阅读顺序、事实修订和维护步骤。阅读顺序链接现有文档，不复制架构全文，也不重写已定稿的 API。

维护步骤按 W6 移交写清这些事实：

- 生产模式清空 `AMR_DEV_ROOT`，资源来自可执行文件旁的 `runtime/`，或来自绝对路径 `AMR_RUNTIME_ROOT`。两个根互斥。开发模式才用仓库内的 `AMR_DEV_ROOT`。
- 数据目录用 `AMR_DATA_DIR`。未设置时 Windows 默认是 `%LOCALAPPDATA%/AccessibleMultimodalRetrieval`。索引在该目录的 SQLite 中，源文件不作为可编辑原件存进库。
- `AMR_JAVA` 指向 Java 可执行文件；未设置时从 PATH 使用 `java`。PDF 文本仍走本机 Apache Tika 4.0.0。空资源根时，启动检查逐项列出缺失的桥接库、模型、分词器、Tika 与 Java。
- 取消停在安全点，已提交的索引保留，对同一目录再次增量即可续建。增量复用比较内容标识、解析器名称与版本、切块版本、模型标识和向量维度。
- 第二实例遇到写锁时的可见结果、损坏向量的诊断、源文件被移动或删除后的打开失败、清空只作用于应用索引和目录记录。这些行为引用 W6 已有日志；尚未回填的双窗口、ACL 和查看器细节写成待测，不写成已通过。
- 日志只记路径、大小、耗时和错误类型，不记文件正文。D2 抽查当前日志字段，把结果写进维护步骤。发现正文落入日志时，作为 D4 的小修复；不为此新建一套日志框架。

架构回写限于已经决定的事实：文本与图像推理在生产路径上是原生 ONNX Runtime CPU；产品向量库存系统 SQLite；Chroma 与 `engine/` 留在开发期评测；PDFium 仍未接入，PDF 继续用 Tika。历史周报里的当时测量保持原句，不回改 W2–W6 的数字。

## 5. 用户手册与无障碍

`reports/week7/用户手册.md` 面向使用者。安装一节写 Windows x64 候选的资源前提和数据目录，并写明当前还没有面向三平台的安装器。功能一节按文件库、搜索、结果、设置说明选择目录、增量、取消、筛选、出处和用系统应用打开原文件。系统查看器不能定位到页或段时，手册直接说明这一限制。

无障碍一节吸收 W5 草稿里已经核对过的键盘表、NVDA 路径、高对比和 100% / 150% / 200% 字号。引用 [W5 验收矩阵](../week5/E_验收矩阵.md) 和 [NVDA 实机记录](../week5/logs/screen_reader_nvda_session.md)。草稿附录中的 `AMR_DEV_ROOT` 启动块改到维护文档的开发模式，不再作为用户安装步骤。VoiceOver、macOS 和 Linux 各留一行未验证。Accessibility Scanner 与 WAVE 的适用性差异沿用 W5 结论，不为本周临时做网页或 Android 目标。

独立试用在 W6 仍是 0 人。手册不写“试用者未发现问题”。若 11/20 前没有新的试用记录，周报保持 0 人，并把 T1–T5 留给 W8。

## 6. 开源合规

`reports/week7/开源合规报告.md` 用一张表覆盖运行时实际加载的组件，每行包含名称、版本、获取位置、许可证、NOTICE 或归属文本路径、进入公开包的结论。清单从这些来源抄版本，不凭记忆填写：

- `apps/desktop/pubspec.lock` 与五个核心包的锁文件
- Windows 候选使用的 ONNX Runtime 1.23.2 CPU，及其 `ThirdPartyNotices.txt`
- 本仓库的 `native/onnx` 桥接库
- Java 运行时与 Apache Tika 4.0.0。Tika 的 NOTICE 在 `tools/tika-app/`。当前产品调用外部 `java`，报告写明尚未随包携带 JRE
- 系统 SQLite。沿用已记录的 `winsqlite3.dll` 未文档化用途，把是否改带 `sqlite3.dll` 留给 W8
- 文本模型与两个分词器、MobileCLIP 视觉塔和文本塔。文本权重按 ADR 0003 记 Apache-2.0；MobileCLIP 权重记 apple-amlr，公开包排除
- `engine/` 中的 Chroma、TensorFlow 仅作开发期评测，不进入发布包

仓库根 `LICENSE` 保持 Apache 2.0。报告增加一份第三方声明索引，指向各组件自带的 NOTICE，不把第三方正文重抄进仓库。Flutter 构建产生的 `NOTICES.Z` 在报告中单列，说明它覆盖 Flutter 引擎与 Dart 包，不覆盖 ORT、Tika 和模型权重。

公开包若没有图像塔权重，报告给出两种后续方案的许可后果：使用者按研究许可自行准备权重，或在 W8 改用可再分发的图像模型并复验缺件启动。本周不执行换模型。

## 8. 演示脚本

`reports/week7/演示脚本.md` 按约 5 分钟写分镜，供 W8 录像。每段包含画面、操作、旁白和证据文件。建议顺序：

1. 说明离线与本机索引，展示资源根和数据目录，不展示模型下载。
2. 从干净数据目录选择样本文件夹，完成索引进度与一份失败文件的提示。
3. 文本查询、筛选、查看出处，并用系统应用打开原文件。
4. 纯键盘或 NVDA 完成同一查询。高对比或字号只演示已经在 W5 留下记录的设置。
5. 用一句话说明技术路径：解析、ONNX 嵌入、SQLite、融合排序。点明 MobileCLIP 权重不进入公开包，以及图像问句的已知限制。
