# 覆盖率报告

## 命令

每个包在自己的目录里执行。带 `integration` 标签的测试会读 `tokenizer.json`、fp32 ONNX 或数据集，这次排除在外。

```powershell
dart test --coverage=coverage --exclude-tags integration
dart run coverage:format_coverage --lcov --in=coverage --out=coverage\lcov.info --report-on=lib --package=.
```

`lcov.info` 复制到 `reports/week4/coverage/<包名>.lcov.info`。包内的 `coverage/` 仍由 gitignore 忽略。

## 行覆盖率

统计的是各份 lcov 里 `LH` / `LF` 之和。百分数保留两位。数据来自 2026-10-26 的重跑。

| 包 | 行命中 | 套件 | 门槛 | 判定 |
|---|---|---|---|---|
| `core_storage` | 574/666 = 86.19% | `00:02 +23` | ≥ 85% | 通过 |
| `core_retrieval` | 158/164 = 96.34% | `00:02 +9` | ≥ 85% | 通过 |
| `core_pipeline` | 272/298 = 91.28% | `00:03 +23` | ≥ 85% | 通过 |
| `core_parsing` | 979/1091 = 89.73% | `00:06 +98` | 不低于 80% | 通过 |
| `core_embedding` | 1250/1458 = 85.73% | `00:11 +93` | 不低于 85% | 通过 |

`core_embedding` 与第 3 周的 1250/1458 = 85.73% 相同。`core_parsing` 第 2 周快照是 949/1043 = 90.99%，当时插桩行数是 1043。这次库的插桩行数是 1091，行命中率 89.73%，仍高于 80%。

`core_storage` 的分母从 573 涨到 666（+93 行），原因是新增了 `ScoredCandidate`、`rowIdOf` 与三阶段向量查询（`vector_query.dart` 的扫描/回表/展示三段、`float32View`、`dotFloat32`）。命中随之增加，新增 10 条用例后为 574 行，比例回到 85% 以上。

`core_pipeline` 从 280/298 = 93.96% 变为 272/298 = 91.28%：产物存在性那条用例归入 `integration` 标签后，`PersistentOnnxRuntime.python` 工厂的 8 行不再被默认套件覆盖。这是**下降**，不是提升；门槛 85% 仍然满足。
