## 4. 联调与测试矩阵

每条用例记录构建版本、环境、输入、步骤、期望、实际和证据。统一使用通过、失败、未测、阻塞、不适用五种状态。真实模型与平台测试单列。

| 编号 | 层级 | 场景与验收标准 |
|---|---|---|
| UT-01 | 单元 | 五个核心包默认单元套件全绿。重点检查坏文件/编码、嵌入边界、写入回滚、索引代次、筛选和取消。每包按 `LH/LF` 计算，分别达到 ≥90%，报告分母及新增覆盖行为 |
| IT-01 | 集成 | 真实文件、模型和 SQLite 走解析 → 嵌入 → 持久化 → 召回。文本及图像各验证可用通道，检查维度、模型版本、页码与 UTF-16 偏移 |
| IT-02 | 集成 | 混合好坏文件、取消/重试、模型或 Java 缺失、SQLite 权限/锁冲突、关闭时仍在索引。已提交数据可读，失败任务可恢复，并发写入或第二实例行为可解释 |
| E2E-01 | 原生桌面 | 从干净数据目录启动，原生选择目录、索引、筛选、查看出处、用系统应用打开 TXT/PDF 或图像，重启后仍能检索。失败打开有可操作提示 |
| E2E-02 | 原生桌面 | 原样重建复用，修改后重新索引，处理已移动或删除的文件。清空只影响应用索引与目录记录，样本源文件哈希一致 |
| E2E-03 | 无障碍 | 纯键盘走通主流程。NVDA 验证进度、完成和错误播报、对话框退出及焦点恢复，固定窗口复查高对比与字号。VoiceOver 在 macOS 单独记录 |
| E2E-04 | 跨平台 | Windows、macOS、Linux 分别记录 CI 构建、启动、真实运行时和原生操作。CI 产物、受控实机和辅助技术结果分列 |
| UX-01 | 可用性 | 沿用 W5 T1–T5，记录参与者逐任务完成、用时、求助、障碍及复测。招募受阻时记录开发者走查与待补项 |
| ST-01 | 压力 | 约 1k / 5k / 10k 内容块逐级压测，记录实际文件与块数。覆盖批量导入、交互中取消、增量重建、连续查询、重启和坏文件混入。无崩溃、无数据损坏，记录耗时和峰值内存 |
| SEC-01 | 安全 | 本地资源就绪后隔离外网，执行导入、查询、打开与重启。保留网络隔离有效性及应用与子进程的连接观测，单列外部查看器行为 |

核心包在各自目录执行 `dart analyze`、`dart test --exclude-tags integration --coverage=coverage`，以 W4 的 LCOV 命令为基准限制统计到 `lib/`。桌面在 `apps/desktop/` 执行 `flutter analyze` 和 `flutter test`，按 README 启用 `AMR_E_REAL_RUNTIME` 复跑真实集成。候选构建用相应平台的 `flutter build <target> --release`。首次记录测试提交和工具版本，最终统一绑定候选构建重跑。

## 5. 性能基准与优化判据

使用同一主机、电源模式、构建类型、模型版本、语料哈希、查询集、索引规模与筛选配置。分别记录冷启动和热态。在测试前固定次数与查询顺序，建议热态每配置至少 30 次，冷启动至少 5 次。报告原始样本、样本数、p50/p95 和峰值。计时拆分到模型加载、推理、向量扫描、融合和端到端；内存统计覆盖 Flutter、worker 和相关子进程，注明采样口径。

| 指标 | 采样内容 | 优化候选 |
|---|---|---|
| 推理延迟 | 冷加载、热态每条、文本/图像分别记录 | 模型会话复用，检查预处理、复制和运行时切换成本 |
| 向量与端到端搜索 | 固定查询的向量扫描和 UI 提交至结果可操作时间 | 检查回表次数、过滤顺序、重复编码及数据复制 |
| 内存与长任务 | 导入与检索的进程树峰值，连续查询后的稳定值，取消至安全点耗时 | 减少临时缓冲和并发峰值，验证退出后的资源释放 |

用 D1 数据设定本机预算，提交优化前写入报告。每项优化用同配置复测并检查排名、出处和增量结果。运行时变更涉及数值差异时，先定容差和 Top-K 对照规则。只有重复测量支持且正确性回归通过的变化计入收益。三项指标分别给出结果，未达到预算的项保留瓶颈和后续动作。

## 6. 缺陷与离线安全

- P0 包括数据丢失、源文件被错误修改、隐私数据外发和无法启动。P1 包括核心流程阻断、无法安全退出或恢复、键盘或读屏无法完成关键操作。每项记录复现输入、堆栈或日志、修复版本、原条件复测。P0/P1 未清零时暂缓稳定构建签收。
- 静态检查应用和运行时入口的网络请求、遥测、模型获取、日志、临时文件、数据库及进程启动参数。核对本地路径、查询和内容片段是否进入不必要的日志，并检查日志导出后的敏感字段。
- 动态检查覆盖冷启动、索引、查询、清空和退出。观察应用与子进程的 DNS 和出站尝试，配合源文件哈希、数据库路径、临时目录和退出后残留检查。报告写明隔离范围、工具可见性及未覆盖的平台。
- 发布依赖验证从非仓库工作目录启动候选构建，用显式资源配置验证模型、分词器、解析器、SQLite、用户目录和诊断。需要开发环境的结果标为开发链路，另列生产适配阻塞和 W8 发布条件。
