# W06 D5 人工验证清单

使用 D5 Windows x64 候选 `04c22914a86f9cd3d1d6cf9050b4e2e16055627e`。本清单的原生操作、断网和试用由项目开发者或试用者执行，按实际结果回填。Windows 无障碍与显示引用 W5 实测。

## 准备

在仓库根目录用 PowerShell 设置 D5 本地候选和生产资源。用 [候选清单](logs/D5_candidate_manifest.json) 核对 `desktop.exe`、`data/app.so` 和运行资源。受控资源位于本地忽略目录。测试素材均为独立副本。首次导入、断网、长任务和每位试用者各用独立的 `AMR_DATA_DIR`。验证重启和续建时沿用该场次的目录。M01 导入后先做 M03，再做 M04 的清空测试。

```powershell
$repo = (Get-Location).Path
$release = (Resolve-Path '.dart_tool/w06-d5/candidate').Path
$exe = Join-Path $release 'desktop.exe'
$env:AMR_DEV_ROOT = ''
$env:AMR_RUNTIME_ROOT = (Resolve-Path '.dart_tool/w06-d2-ort/local-runtime').Path
$env:AMR_JAVA = 'java'
$manual = Join-Path $env:TEMP ('amr-w06-d5-' + [guid]::NewGuid().ToString('N'))
$env:AMR_DATA_DIR = Join-Path $manual 'data'
$fixtures = Join-Path $manual 'fixtures'
New-Item -ItemType Directory -Force "$fixtures/notes", "$fixtures/archive" | Out-Null
Set-Content -LiteralPath "$fixtures/notes/guide.txt" -Encoding utf8 -Value '离线检索操作指南：文件在本机建立索引，可以按目录与日期查找资料。'
Set-Content -LiteralPath "$fixtures/archive/old.txt" -Encoding utf8 -Value '旧版离线检索记录，与新版操作指南分开存放。'
Set-Content -LiteralPath "$fixtures/bad.docx" -Encoding utf8 -Value 'deliberately invalid DOCX archive'
Copy-Item -LiteralPath "$repo/datasets/samples/sample.pdf" -Destination "$fixtures/notes/sample.pdf"
Copy-Item -LiteralPath "$repo/datasets/samples/sample.png" -Destination "$fixtures/sample.png"
Get-ChildItem -LiteralPath $fixtures -Recurse -File | ForEach-Object { $_.LastWriteTime = [datetime]'2020-01-01' }
(Get-Item -LiteralPath "$fixtures/notes/guide.txt").LastWriteTime = [datetime]'2026-10-29T12:00:00'
Get-FileHash -LiteralPath $exe, "$release/data/app.so"
$fixtures
Start-Process -FilePath $exe -WorkingDirectory $manual
```

## 原生主流程与 W5 无障碍证据

### D5-M01 启动与原生导入

1. 从准备步骤创建的仓库外工作目录启动。核对生产诊断显示原生 ONNX Runtime CPU 且资源就绪。
2. 在“文件库”打开“选择目录”。先取消，核对目录栏保持原值。再打开选择器，输入 `$fixtures` 的实际路径并确认。
3. 激活“建立 / 增量更新索引”，等待结束。核对 4 个正常文件入库、`bad.docx` 单独报错、搜索仍可用。保存诊断、计数和错误提示，继续 M03。

### D5-M02 键盘与 NVDA（沿用 W5）

引用 W5 的键盘操作确认和 NVDA 2026.2.0.57664 会话原文，覆盖搜索、读取来源、打开文件及修正日期错误。自动播报、精确焦点恢复及整体判定沿用 W5 的部分验证记录。 [W5 验收矩阵](../week5/E_验收矩阵.md) · [W5 NVDA 原始记录](../week5/logs/screen_reader_nvda_session.md)

### D5-M03 搜索、出处与查看器

1. 按 Ctrl+L 聚焦“搜索本地内容”，搜索 `离线检索`。用键盘找到 `notes/guide.txt`，核对文件名、片段、完整路径、相对路径和可用的 UTF-16 偏移。对文本激活“打开原文件”，确认查看器实际显示本次夹具。
2. 回到搜索页，将“文件类型”改成 PDF 并再次提交。核对结果条件、`notes/sample.pdf` 的出处页、偏移和片段。打开原文件，记录查看器名称、实际文件和是否定位到所示页。
3. 改用图片类型重提，找到 `sample.png`，核对来源和图像元数据并实际打开。如果结果缺少目标文件，记录查询和筛选，尝试清除其他筛选或改用更贴合样本的查询。逐类关闭查看器回到应用，保存能核对实际打开文件的证据。

### D5-M04 更新、取消、退出与权限恢复

1. 对 M01 的目录执行一次“建立 / 增量更新索引”，记录原样复用 4 个正常文件和坏件处理。备份夹具副本的 `notes/guide.txt`，追加一个可检索的独特标记，再次更新。核对只重写该文件，查询能命中标记。记录复用、写入和错误计数。
2. 搜到 `notes/sample.pdf` 后，将该测试副本暂移到夹具目录外。保留旧结果，激活“打开原文件”，记录文件缺失提示。恢复文件原路径，按原步骤重试并确认查看器打开。
3. 用 M06 的大夹具副本和独立数据目录启动。等至少一个可识别文件提交，激活“取消索引任务”。记点击至界面回到安全状态的耗时和已提交计数，搜索一份已提交文件，再用同一目录续建。核对已提交文件被复用，剩余文件写入，坏件仍单列。
4. 另开一轮长任务，在至少一份文件提交后用窗口关闭按钮退出。记录退出耗时和是否无响应。用同一数据目录重启，搜索已提交文件并续建。若索引先结束，增加测试副本中的样本量后重试，记录实际触发时机。
5. 在新的测试场次用相同 `AMR_DATA_DIR` 启动窗口 A 和 B。A 对新文件建库期间，在 B 尝试建库，再尝试确认清库，记录写入冲突提示。若任务结束太快，分两轮重现。待 A 完成后在 B 重试建库，核对复用、目录记录和旧结果。
6. 用独立测试数据目录和受限账号或 Windows ACL 复现写入被拒。先记原权限，再记录启动或写入时的提示。恢复原权限后重启或重试，确认可索引、查询和继续使用已有记录。保存权限配置和恢复结果。 [D3 并发与权限步骤](D3_人工验证清单.md)
7. 恢复测试副本的原始内容后记录源文件相对路径及 SHA-256。确认该场次可清空，再执行“清除全部索引”并确认。验证目录记录消失、查询无结果、源文件仍能通过系统打开，复算哈希并对照。

### D5-M06 断网闭环、出站观测和桌面压力

**断网与网络观测**

1. 准备空数据目录、本地小夹具和已经就绪的生产资源。记录 UTC 起止时间、监测工具及规则。使用可按进程关联的工具，例如已配置网络和 DNS 事件的 Sysmon，先做一次无敏感信息的联网对照，确认测试端点可达并能捕获预期事件。对源文件记录相对路径和 SHA-256，供退出后比较。
2. 隔离外网后对同一端点重复检查，保存隔离有效性证据。保持隔离，用候选版冷启动，导入混合夹具、搜索、筛选 PDF、用系统查看器打开，再退出重启并重查。最后清空索引并退出。
3. 按时间和 PID 提取应用、Java/Tika 子进程及系统查看器的 DNS、TCP、UDP 或阻止事件。记录 PID、进程名称、归属和监测覆盖范围。查看器结果单列。若只做了连通性检查，将出站观测标为未测。
4. 核对退出后的应用和 Java 子进程状态，记录独立数据目录与临时目录的残留文件及大小，并对照夹具相对路径和 SHA-256。恢复网络设置。保存隔离前后对照、实测记录和已检查敏感字段的日志。 [D4 断网与残留检查](D4_人工验证清单.md)

**10k 桌面压力**

2026-11-15 已记录 D5 Windows 候选的导入、取消续建、增量与清空。全库和 TXT 各有 30 次桌面样本，实际查询为 `0`，本机中文输入待复测。 [桌面结果及截图](性能优化基准报告.md#2026-11-15-windows-10k-桌面实测)

2. 在独立空库重复导入，等写入开始且已有文件提交后，从界面触发取消。按 M04 核对已提交结果、退出重启、续建、修改一个 TXT 后的增量更新和清空。记录从点击取消至界面恢复可操作的时间及各阶段计数。测试结束时核对源文件仍在。

4. 检查各轮是否崩溃、无响应或出现数据损坏。记录续建和重启后的检索结果、取消延迟、工作集及未测项。 [D4 桌面压力步骤](D4_人工验证清单.md)

## 性能复测

### 大库检索与扫描

1. 固定主机、电源方案、Dart AOT、模型与资源哈希、查询顺序及基准数据。从 `.dart_tool/w06-d5/pressure` 复制 `tiny`、`image-only` 和三份 `scale-*.sqlite` 到独立工作目录，按 D4 绑定清单核对快照哈希。快照缺失时，按性能报告的复跑命令重建，并记录新快照哈希。 [D4 快照与资源哈希](benchmarks/D4_bindings.json)
2. 用 D5 探针和现有 `week6_pressure.ps1 -Mode measure` 采集基线，使用新报告路径。每个配置预热后记录 30 个样本。固定 `离线检索`，复测 1k/5k/10k 全库及 `a/` 前缀、普通向量扫描和独立 10k 全同分扫描。沿用管道 Top-5、独立扫描 Top-50 的口径。
3. 在同一 10k 快照和查询上增加分段计时，分别量关键词候选聚合、正文与展示字段回表、向量扫描、融合和完整管道，同时记录候选及回表行数。根据实测热点试验先选候选再回填正文，或独立验证过滤与扫描改动。每次只测一项改动，保留相同条件的对照。
4. 在相同配置重跑 30 次并保留原始样本、p50/p95、峰值内存和正确性对照。比较排名、分数、路径、页码、UTF-16 偏移、通道及片段，补查去重、混合查询和增量索引。对照 D5 的 10k 全库热管道 p95 **463.18 ms** 与 **200 ms** 目标，以及向量扫描 **60 ms** 参考门槛。5k 全库热管道与 10k 筛选、全同分的未达项也逐项回填。 [基准命令与 D5 数据](性能优化基准报告.md) · [D4 判据](benchmarks/D4_acceptance.md)

第 1–2 步可在仓库根目录用 PowerShell 7.4 或以上执行。使用准备步骤中的 `AMR_RUNTIME_ROOT`。每次复测创建新的工作目录和报告路径。

```powershell
$benchId = 'D5_recheck_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff')
$benchInput = '.dart_tool/w06-d5/pressure'
$benchWork = Join-Path '.dart_tool/w06-d5' $benchId
$benchReport = Join-Path 'reports/week6/benchmarks' "$benchId.json"
$benchBindings = Get-Content -LiteralPath 'reports/week6/benchmarks/D4_bindings.json' -Raw |
    ConvertFrom-Json -AsHashtable
foreach ($snapshot in $benchBindings.sqliteSnapshots.GetEnumerator()) {
    $inputPath = Join-Path $benchInput $snapshot.Key
    if ((Get-FileHash -LiteralPath $inputPath -ErrorAction Stop).Hash -ne $snapshot.Value) {
        throw "快照哈希不匹配：$inputPath"
    }
}
New-Item -ItemType Directory -Path $benchWork -ErrorAction Stop | Out-Null
foreach ($item in @('tiny', 'image-only') + @($benchBindings.sqliteSnapshots.Keys)) {
    Copy-Item -LiteralPath (Join-Path $benchInput $item) -Destination $benchWork -Recurse -ErrorAction Stop
}
& './apps/desktop/tool/week6_pressure.ps1' -Probe '.dart_tool/w06-d5/d5-pressure.exe' `
    -Mode measure -Scratch $benchWork -RuntimeRoot $env:AMR_RUNTIME_ROOT -Report $benchReport
```

### CLIP 文本推理

1. 使用同一候选、原生桥、ORT、CLIP 文本模型、分词器、线程配置和电源方案。在空闲主机复跑 `measure`，记录电源方案、CPU 负载和构建信息，保留不同场次各自的原始输出。
2. 读取测量报告最后一个冷态轮次的 `forwardMs`，按文本塔模型路径取 30 条热前向样本。单列会话加载、MiniLM 和 CLIP 视觉数据。按最近秩法计算 p50/p95，并与 D5 的 **38.49 ms** 和 **30 ms** 预算对照。
3. 若复测仍超预算，记录可重复的配置、负载和瓶颈，再根据分段数据决定优化。修改运行时前先定数值容差和 Top-K 对照规则，改动后用相同样本复测延迟及检索结果。 [性能报告的采样口径](性能优化基准报告.md)
