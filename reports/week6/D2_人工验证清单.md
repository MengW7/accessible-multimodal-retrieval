# W06 D2 原生桌面与断网验证清单

本页操作、截图及网络隔离由你执行。每项记录系统版本、测试日期、构建哈希、实际结果和证据路径。Windows x64 的自动化结果见 [D2 阶段记录](W06_D2_checkpoint.md)。下列人工项均待回填。

## 准备候选程序和独立数据

在仓库根目录用 PowerShell 执行以下命令。构建目录须包含 `desktop.exe`、Flutter DLL 和完整 `data/`。如果本机资源目录不同，将 `AMR_RUNTIME_ROOT` 改为相应绝对路径。

```powershell
$repo = (Get-Location).Path
$release = Join-Path $repo 'apps/desktop/build/windows/x64/runner/Release'
$exe = Join-Path $release 'desktop.exe'
$manual = Join-Path $env:TEMP ('amr-w06-d2-' + [guid]::NewGuid().ToString('N'))
$fixtures = Join-Path $manual 'fixtures'
$cancelFixtures = Join-Path $manual 'cancel-fixtures'
New-Item -ItemType Directory -Force $fixtures, $cancelFixtures | Out-Null
foreach ($name in 'sample.docx', 'sample.pdf', 'sample.png') {
    Copy-Item -LiteralPath "$repo/datasets/samples/$name" -Destination $fixtures
}
Set-Content -LiteralPath "$fixtures/smoke.txt" -Value '离线检索验证。独立样本标记 D2-original。' -Encoding utf8
foreach ($i in 1..40) {
    Set-Content -LiteralPath "$cancelFixtures/item-$i.txt" `
        -Value ("取消续建样本 $i。 " + ('离线验证保留已提交的记录。' * 24)) -Encoding utf8
}
$env:AMR_DEV_ROOT = ''
$env:AMR_RUNTIME_ROOT = (Resolve-Path "$repo/.dart_tool/w06-d2-ort/local-runtime").Path
$env:AMR_JAVA = 'java' # 也可以指定 java.exe 的绝对路径
$env:AMR_DATA_DIR = Join-Path $manual 'data'
Get-FileHash -Algorithm SHA256 -LiteralPath $exe, "$release/data/app.so"
$fixtures
$cancelFixtures
Start-Process -FilePath $exe -WorkingDirectory $manual
```

哈希对照 [候选构建清单](logs/D2_candidate_sha256.txt)。整个测试沿用同一个 PowerShell 窗口，以便应用每次启动时使用明确的资源和数据目录。

## 人工验收

- [ ] **D2-M01 生产模式首次索引与真实打开（E2E-01）。** 从仓库外工作目录启动。启动诊断应通过并显示原生 ONNX Runtime CPU。用原生文件夹选择器选中 `$fixtures`，建立索引，搜索“离线检索”，筛选 PDF，核对路径、页码和偏移。点击打开并确认实际系统查看器显示 `sample.pdf`，再核对一个 TXT 或图像。记录查看器名称和实际文件。截图建议 `D2-M01-index.png`、`D2-M01-result.png`、`D2-M01-viewer.png`。
- [ ] **D2-M02 增量、退出重启与源文件缺失（E2E-01/02）。** 原样重建应复用四个文件。关闭窗口，确认原进程退出，再用同一 `$manual` 和 `AMR_DATA_DIR` 启动，重复搜索，核对相同的出处。在夹具副本中修改 `smoke.txt` 的标记并增量重建，确认只重算一个文件。随后临时移走已索引的 `sample.pdf`，从旧结果点击打开，应提示源文件不可用；恢复副本后重试。记录复用、更新和恢复结果。
- [ ] **D2-M03 取消与续建（IT-02/E2E-02）。** 选择 `$cancelFixtures` 建库，至少一份完成后点击取消。记录已提交和待处理数，确认提交的文档仍可搜索。对该目录重新建库，核对复用数对应上次已提交数，最终 40 个文件均可用。重建太快来不及操作时，记录该次情况，增加独立样本后再测。截图建议 `D2-M03-cancel.png`、`D2-M03-resume.png`。
- [ ] **D2-M04 断网冷启动闭环（SEC-01）。** 先退出应用，另设一个干净的 `AMR_DATA_DIR`（例如 `Join-Path $manual 'offline-data'`）。记录联网时可达的测试端点与时间，手动隔离外网后对同一端点复查，保留隔离有效性证据。保持隔离，启动候选程序，完成选择目录、首次索引、搜索、PDF 筛选、实际打开，再退出并重启重查。观察候选进程及 Java 子进程的连接，单列系统查看器，记录监测工具、时段和看不到的协议或阶段。只做连通性检查时填写“断网流程已测，出站监测未测”。截图建议 `D2-M04-network.png`、`D2-M04-offline-results.png`。
- [ ] **D2-M05 原生缺依赖诊断。** 关闭候选程序，将 `AMR_RUNTIME_ROOT` 暂指向新测试目录下不存在的绝对路径，再启动。确认缺失 DLL、模型、分词器或 Tika 的检查项可见。还原资源根，将 `AMR_JAVA` 指向一个不存在的 `java.exe` 后重启，应显示 Java 不可运行。恢复环境后重启验证通过。截图建议 `D2-M05-missing.png`。

将证据放到 `reports/week6/logs/` 或 `reports/week6/screenshots/`。macOS 和 Linux 的生产适配、三平台正式安装包、完整 DNS/出站审查分别在后续验收。
