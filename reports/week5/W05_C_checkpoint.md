## 2. 接线与状态管理

- 组合根将同一个 `WorkerLibraryService` 同时注入 `LibraryService` 与 `SearchService`，
  索引、查询和资源关闭共用一条后台生命周期，SQLite/模型不进入 Widget。
- `SearchRequest` 保存已提交的查询和不可修改的筛选快照，表单草稿可以继续编辑，
  结果页始终显示实际已应用条件。无效输入不会提交后台，也会使正在返回的旧结果失效。
- worker 的 `search` 命令直接调用 `RuntimeSession.search`（`DefaultSearchPipeline`），
  不复制融合打分或解析探针终端文本。空库先看实际统计，无需加载模型。
- 新查询到达时协作式取消当前查询，替换旧的待执行项；请求 ID 将响应交回对应 Future。
  控制器再用查询代次阻止旧响应回写页面。取消后的后台收尾仍计为在途任务，防止 UI
  提前开放索引写入而与旧查询冲突。
- `RuntimeSession` 的创建集中到共享入口，保证“先搜索，后执行 B 的增量建库”仍绑定
  解析进度和逐文件回调，不因会话复用丢失文件库状态。
- 文件打开前校验绝对路径和文件存在性，规范本机路径分隔符；原生端再次检查文件，
  以应对校验后文件被移除的竞态。相对探针键不会拿当前工作目录拼成错误来源。
- 原生返回成功仅表示系统接受打开请求。界面明确说明无法保证系统查看器已完成加载或定位页/段。

## 4. 真实模型与新索引结果

验证在新建 `tmp/w05-search-*` 中创建独立数据目录与 6 份输入：4 份 TXT/Markdown、
