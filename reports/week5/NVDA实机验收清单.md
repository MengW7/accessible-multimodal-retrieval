# NVDA 分阶段操作与记录清单

更新日期：2026-11-03。适用：Windows 开发版；对应 A11Y-01、A11Y-02。
本文件是操作指南，**不是已执行结果**。实际结果填写到 [NVDA 会话记录](logs/screen_reader_nvda_session.md)。

## 使用方法

按阶段 0～10 顺序执行。每阶段分“在应用里操作”和“记录到文档”两部分，完成记录后再继续。首轮由开发者执行，参与者类型填“开发者走查”；独立试用者另行记录，不把本清单里的预期写成实际结果。

开始前先打开本清单和会话记录。推荐用 VS Code 编辑 Markdown；也可用记事本。已有结果继续追加，不能覆盖。若再做一场，新建带会话编号的记录文件；同一场的失败和后续复测分开保留。

### 常用键与读屏说明

- “NVDA 键”默认通常是 Insert；Caps Lock 是否可用取决于 NVDA 的修饰键设置。键盘布局与修饰键是两项设置，不能混为一谈。
- Tab / Shift+Tab：移动应用的键盘焦点。Enter / Space：激活按钮。Alt+Tab：切换窗口。
- NVDA+Tab：复读系统焦点；这是主动查询，不是应用自动播报。记录时区分两者。
- 语音查看器：NVDA 菜单 → 工具 → 语音查看器，用文字显示 NVDA 的朗读。焦点位于查看器文本区时更新会暂停，便于选中复制；回到应用再继续。
- 操作控件用 Tab；静态状态、页码、说明等可用 NVDA 对象导航阅读，不要求逐段加入 Tab 顺序。
- 没有数字小键盘时可在 NVDA 设置中选择“笔记本”键盘布局，并单独启用 Caps Lock 修饰键。

| 对象导航动作 | 桌面布局 | 笔记本布局 |
|---|---|---|
| 导航对象回到当前系统焦点 | NVDA＋小键盘减号 | NVDA＋Backspace |
| 进入第一个子对象 | NVDA＋小键盘 2 | NVDA＋Shift＋↓ |
| 下一个同级对象 | NVDA＋小键盘 6 | NVDA＋Shift＋→ |
| 上一个同级对象 | NVDA＋小键盘 4 | NVDA＋Shift＋← |
| 返回父对象 | NVDA＋小键盘 8 | NVDA＋Shift＋↑ |
| 朗读当前导航对象 | NVDA＋小键盘 5 | NVDA＋Shift＋O |

桌面布局使用数字小键盘时关闭 Num Lock。对象导航移动的是阅读对象，不一定改变键盘焦点；阅读完后用 Tab 继续操作之前先用 NVDA+Tab 确认真实焦点。遇到读不出的内容，记录已尝试的方法，不凭看见文字就判读屏通过。

依据：[NVDA 修饰键](https://download.nvaccess.org/documentation/userGuide.html#TheNVDAModifierKey)、[对象导航](https://download.nvaccess.org/documentation/userGuide.html#ObjectNavigation)、[语音查看器](https://download.nvaccess.org/documentation/userGuide.html#SpeechViewer)。

### 每阶段如何复制朗读

1. 先在应用里完成该阶段，记住起止位置和关键操作；不要边操作边在记录文档中输入。
2. Alt+Tab 切到“语音查看器”。必要时用 Tab 进入显示朗读内容的文本区域。
3. 选中本阶段与被测应用有关的内容，Ctrl+C。可用方向键、Home/End 配合 Shift 选择；内容很少时可 Ctrl+A 全选再复制。
4. Alt+Tab 切到会话记录的编辑器，找到对应阶段，选中“【阶段N朗读粘贴处】”并 Ctrl+V。只替换这个占位符，不要全选覆盖整个记录。
5. 手工填写“实际按键、操作结果、焦点、鼠标/帮助、判定”。Ctrl+S 保存。
6. Alt+Tab 回到应用，NVDA+Tab 确认焦点，然后开始下一阶段。

语音查看器会包含切窗口和编辑器的朗读。可以只选相关片段；若粘贴整段，标明测试起止，不把编辑器内容当成应用朗读，也不删掉失败证据。截图、录屏、人工逐字记录也可作补充；语音查看器不是唯一取证方式。复制/补写造成的切窗属于取证操作，应与测试应用自身的焦点返回场景区分。

### 判定规则

- 通过：本阶段需要的操作和信息均已实际验证。
- 部分通过：只验证了一部分，或用了替代路径；明确未完成的子项。
- 失败：实际操作不能满足要求，保留步骤和表现，修复后另记复测。
- 未测/环境阻塞：没执行或缺依赖，说明原因，不推断通过或软件缺陷。
- 在应用的某段用了鼠标，该段不能证明纯键盘完成；记录使用位置。是否独立试用取决于参与者身份。
- 首次阅读本清单或第一次用 NVDA 不熟练时，可先练习；正式记录开始后保留失败及求助。播报措辞不必与预期逐字一致，应判断名称、角色、值、状态是否准确可理解。

## 阶段 0：准备工具、样本和记录文档

### 在电脑上操作

1. 启动 NVDA，确认能读中文。NVDA+N → 帮助 → 关于，查看版本。
2. NVDA+N → 选项/首选项 → 设置 → 键盘，确认桌面/笔记本布局以及已启用的 NVDA 修饰键。菜单译名可能随语言版本不同。
3. NVDA+N → 工具 → 语音查看器，打开显示窗口。不要同时运行另一款读屏软件。
4. 打开 [会话记录](logs/screen_reader_nvda_session.md)，填写开场信息。保留本指南，测试中用 Alt+Tab 切换。
5. 确认本次输入文件夹存在：
   
   E:\Project\accessible-multimodal-retrieval\tmp\w05-acceptance-1ca1c8c4\fixtures

   其中应有 archive/old.txt、notes/guide.txt、notes/sample.pdf、sample.png、bad.docx。bad.docx 故意损坏，用于错误检查，不要修复或替换它。
6. 关闭旧的检索应用窗口，确保下一阶段使用新启动的实例。不要关闭其他无关软件或清空评测索引。

### 记录到文档

1. 在会话记录的“开场信息”填写日期、操作者类型、NVDA 版本、布局、修饰键、系统和显示条件；不知道的项目写“未记录”，不要沿用旧清单固定值。
2. 切到语音查看器，复制能说明 NVDA 正常工作的相关文字；切回文档，替换“【阶段0朗读粘贴处】”。菜单播报只证明工具准备，不证明被测应用可访问。
3. 填写工具是否可用、五个样本是否齐全，保存 Ctrl+S。没有朗读文字时如实写“未采集”；若中文语音或样本未准备好，先停止后续阶段并记录环境阻塞。

## 阶段 1：启动受测程序并固定本场数据

### 在电脑上操作

1. 如果刚修改应用代码，应先在 apps/desktop 中执行 flutter build windows --release --no-pub，构建成功后再测试。构建失败则记录环境/构建问题，不继续使用旧程序冒充新版本。
2. 在 PowerShell 中执行以下命令一次。它为本场生成独立数据目录，环境变量只作用于当前终端及其子进程：

```powershell
cd E:\Project\accessible-multimodal-retrieval
$env:AMR_DEV_ROOT = (Get-Location).Path
$nvdaSession = 'nvda-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
$env:AMR_DATA_DIR = Join-Path $env:AMR_DEV_ROOT "tmp/$nvdaSession/data"
Write-Output "本场数据目录：$env:AMR_DATA_DIR"
git rev-parse HEAD      
Get-FileHash -Algorithm SHA256 -LiteralPath '.\apps\desktop\build\windows\x64\runner\Release\desktop.exe'
Get-FileHash -Algorithm SHA256 -LiteralPath '.\apps\desktop\build\windows\x64\runner\Release\data\app.so'
& '.\apps\desktop\build\windows\x64\runner\Release\desktop.exe'
```

3. 保留这个 PowerShell 窗口，阶段 10 要从同一个终端重新启动；不要重新生成会话名，否则会换成空库。
4. Alt+Tab 到应用，等待本地运行依赖检查结束，用 NVDA+T 确认活动窗口标题，再用 Tab 和 NVDA+Tab 探索首屏。
5. 检查是否能感知就绪/阻塞状态、当前文件库页面、开发模式说明。新库应为 0 文档。依赖阻塞时保存实际错误，先解决或标记后续阶段未测，不跳过错误假定就绪。

### 记录到文档

1. 先复制终端显示的数据目录、提交编号和两个实际构建哈希，填入会话开场信息。Git HEAD 不能代表未提交改动，另外注明是否有工作区修改。
2. Alt+Tab 到语音查看器，复制**应用首屏**的实际朗读；切回会话记录替换“【阶段1朗读粘贴处】”。
3. 填写首屏索引数、依赖是否就绪、焦点和提示是否可感知，Ctrl+S。记录完再回应用。

## 阶段 2：四页导航与键盘焦点

### 在应用里操作

1. NVDA+Tab 确认焦点，用 Tab/Shift+Tab 找到“文件库、搜索、结果、设置”导航。
2. 每到一个导航控件，先听名称/选中状态，再用 Enter 或 Space 切换。按实际顺序逐页操作，最后回文件库。
3. 检查每次切换是否能识别页面、是否能继续到达主要控件、焦点边框是否可见。
4. 不预设“Tab 几次必到”。如果失焦或绕不出来，记录最后的控件和按键，不用鼠标补救后直接记通过。

### 记录到文档

1. Alt+Tab 到语音查看器，复制各页导航和选中状态的相关朗读。
2. Alt+Tab 到记录文档，替换“【阶段2朗读粘贴处】”；手工填写实际切页顺序、激活键、焦点去向，以及是否用了鼠标或帮助。
3. 填写能否到达四页、是否有陷阱，选择判定，Ctrl+S。回应用文件库后继续。

## 阶段 3：目录选择、首次导入和失败信息

### 在应用里操作

1. Tab 到“选择目录”，Enter 打开系统文件夹对话框。
2. 在对话框按 Ctrl+L 或 Alt+D 尝试聚焦地址栏，输入阶段 0 的完整样本目录，Enter 进入。
3. 用 Tab 找到并确认系统“选择文件夹/选择目录”按钮。系统对话框译名与布局以实际为准，不按盲目的固定 Tab 次数。
4. 返回应用后，检查“目录的绝对路径”是否正确，并用 NVDA+Tab 确认焦点。
5. 若系统选择器无法操作，记录失败位置；可退出对话框后手动输入路径继续，但必须分记“原生选择器未通过、手动路径导入结果”，不能将替代操作签收为选择器通过。
6. Tab 到“建立 / 增量更新索引”，Enter。听取运行与完成状态；模型首次加载可能需等待，记录等待期间能否感知状态、导航是否仍可操作。
7. 首次空库导入这五份输入，预期为新写入 4、复用 0、失败 1。用对象导航阅读逐文件结果，检查坏 DOCX 原因及好文件成功信息是否可读。静态文字不是按钮，不要求它逐条获得 Tab 焦点。

### 记录到文档

1. Alt+Tab 到语音查看器，复制选择器名称/返回状态、应用进度和完成提示、坏文件原因。长内容可分几次复制粘贴，但都放在阶段 3。
2. 在“【阶段3朗读粘贴处】”粘贴实际内容；填写实际目录、写入/复用/失败数、等待情况及使用的对象导航按键。
3. 分别判定“原生目录选择”“导入/完成状态”“逐文件信息”，再给阶段总体判定。用了手动输入等替代路径要注明，Ctrl+S。不要把预期计数粘成实际计数。

## 阶段 4：增量复用

### 在应用里操作

1. 不修改输入文件，不清空索引。仍在本场数据目录中。
2. Tab 到“建立 / 增量更新索引”或该目录对应的增量重建按钮，Enter，记录实际使用哪个入口。
3. 等待完成，用对象导航检查汇总和逐文件状态。
4. 预期新写入 0、复用 4、失败 1；文档数仍为 4。同一个坏文件再次失败是本样本预期，不等于增量故障。

### 记录到文档

1. Alt+Tab 到语音查看器，复制本次增量完成/复用的实际朗读。
2. 切回记录文档，替换“【阶段4朗读粘贴处】”；填写所用入口、实际计数和更新前后文档数。
3. 没能读取汇总时写明“画面可见但读屏未读到”及尝试方法，不能只据视觉判读屏通过。判定后 Ctrl+S。

## 阶段 5：搜索与阅读结果来源

### 在应用里操作

1. 在应用按 Ctrl+L，用 NVDA+Tab 确认是否进入“搜索本地内容”输入框。
2. Ctrl+A 选中该输入框旧值，输入“离线检索”，Enter 提交。Ctrl+A 只在确认位于输入框后使用。
3. 等待搜索结束，先听应用是否自动提示完成，再主动探索结果。主动阅读与自动完成播报分开检查。
4. 用对象导航读取至少一个结果的文件名、片段、来源路径、相对路径和可用页码/偏移。找不到静态内容时记录对象树探索路径。
5. 检查能否用 Tab 到达打开按钮及“修改搜索条件”；不要把 20 条结果误当作 20 个文件。实际数量按本次显示填写，不要求固定为 20。

### 记录到文档

1. Alt+Tab 到语音查看器，复制本次焦点、完成提示和结果来源信息。
2. 切回文档替换“【阶段5朗读粘贴处】”；填写查询词、结果数及至少一个实际来源。
3. 分别写“自动听到的状态”和“主动用 NVDA 查询读到的信息”，填写结果内容是否完整可读、焦点情况和判定，Ctrl+S。

## 阶段 6：PDF 筛选、打开文件和返回焦点

### 在应用里操作

1. 从结果页 Tab 到“修改搜索条件”，Enter。
2. Tab 到“文件类型”，Enter/Space 尝试展开；用方向键选择 PDF，Enter 确认。若无法展开或选择，记录具体按键和表现。
3. 确认路径、日期条件为空，Tab 到“开始搜索”，Enter。选择条件后必须重新提交。
4. 在结果页检查本次条件为 PDF，并读取 sample.pdf 来源、片段及可用页码。按实际信息判断，不预填第几页。
5. Tab 到“打开原文件：sample.pdf”，先记录当前焦点，再 Enter。
6. 等待系统查看器，核对打开的文件确实对应结果来源。应用“已请求打开”只表示发出请求，不能代替查看器显示成功。
7. **在切到语音查看器取证前**，先 Alt+Tab 返回检索应用，立即 NVDA+Tab，检查焦点及能否继续操作。否则额外取证切窗会干扰返回焦点的观察。
8. 若没有默认查看器、文件未打开或焦点异常，记录环境/实际表现。系统查看器不能跳页时说明定位限制，不把应用有页码解释为已精确跳转。

### 记录到文档

1. 完成第 7 步后再 Alt+Tab 到语音查看器，复制筛选选择值、PDF 来源、打开提示与返回焦点信息。
2. 切回文档，替换“【阶段6朗读粘贴处】”；填写打开的是哪个文件、查看器名称、是否真正显示，以及返回后的焦点。
3. 分别判定下拉选择、PDF 筛选、实际打开、焦点返回；未尝试的项目填未测，Ctrl+S。

## 阶段 7：无效日期与错误恢复

### 在应用里操作

1. Ctrl+L 回搜索页。保留“离线检索”查询，文件类型可保留 PDF，记录实际条件。
2. Tab 到“修改时间晚于日期”，Ctrl+A，输入 2026-02-30。
3. Tab 到“开始搜索”，Enter，观察是否仍能操作以及错误是否自动播报。
4. 用对象导航尝试读取“修改日期不存在”等实际提示，分清自动提示和主动读到。
5. 返回日期框，Ctrl+A 后 Backspace 清空；再次提交搜索，检查是否恢复出结果。
6. 若操作失败，保留第一次失败记录。补救后另写实际恢复步骤，不删除原错误。

### 记录到文档

1. Alt+Tab 到语音查看器，复制错误出现和修正重提后的相关朗读。
2. 切回文档替换“【阶段7朗读粘贴处】”；填写错误日期、修正方式、修正后结果。
3. 单列错误能否主动读到、能否自动感知、修正后的焦点是否可继续操作。选择判定，Ctrl+S。

## 阶段 8：高对比、三档字号与设置可操作性

### 在应用里操作

1. 用键盘切到设置，Tab 到“高对比模式”，Space 切换到开启，检查名称和开关值是否读出。
2. Tab 到“明暗主题”，分别选浅色、深色。每次确认选择值是否读出，主要文字和焦点是否可辨；这些是局部检查，不等于所有颜色状态测量。
3. 在“文字大小”依次选择 100%、150%、200%。每档确认选择值、能否读到控件名称，是否可以继续 Tab 到主要操作；记录窗口和系统缩放条件，不临时放大窗口来掩盖裁切。
4. 200% 下返回搜索，检查输入、类型筛选和提交是否仍可到达；返回设置时检查是否仍为 200%。
5. 此阶段结束保留一套明确设置，例如“深色、高对比开、200%”，实际选择写入记录，供阶段 10 核对。

### 记录到文档

1. Alt+Tab 到语音查看器，复制高对比开关、主题和三档字号选择的实际朗读。
2. 切回记录文档替换“【阶段8朗读粘贴处】”；填写每档能否继续操作、有无裁切/失焦和结束时设置值。
3. 写清只检查了哪些页面/窗口条件，未检查四页全部状态则保留缺口。需要截图时另外保存，不覆盖既有图片。判定后 Ctrl+S。

## 阶段 9：清空确认弹窗、焦点循环与退出

### 在应用里操作

1. 回文件库，Tab 到“清除全部索引”，Enter。
2. 先听弹窗名称及焦点，用 NVDA+Tab 确认默认是否为“保留索引”。
3. 用对象导航读取清除范围、当前数据库位置、源文件保留说明。
4. Tab 和 Shift+Tab 在弹窗内移动，检查焦点是否仍在弹窗，能否到达两个按钮。
5. 按 Ctrl+L，检查弹窗是否保持、背景页是否没有切到搜索。再按 Esc 退出。
6. 立即 NVDA+Tab，记录是否返回“清除全部索引”。**完成这项观察后再切窗取证。**
7. 本阶段不激活“确认清除索引”，保留数据用于重启检查。若误清空，记录实际发生的事，阶段 10 的索引恢复不可再按原预期签收。

### 记录到文档

1. Alt+Tab 到语音查看器，复制弹窗标题、说明、默认焦点、循环操作、Esc 后焦点的相关内容。
2. 切回文档替换“【阶段9朗读粘贴处】”；填写是否误激活清空，Ctrl+L 是否切页，退出后的焦点。
3. 分别填写弹窗可读性、默认焦点、循环、退出/恢复判定，Ctrl+S；截图若需要，必须实际显示弹窗。

## 阶段 10：正常退出、重新启动与汇总

### 在应用里操作

1. 确认索引及设置保存没有仍在进行；如仍在处理，记录等待情况。
2. 在应用按 Alt+F4 正常退出。观察窗口是否关闭及是否有异常提示。
3. Alt+Tab 到阶段 1 留下的同一个 PowerShell，只执行下面的启动行，**不要重新执行阶段 1 的会话目录生成命令**：

```powershell
& '.\apps\desktop\build\windows\x64\runner\Release\desktop.exe'
```

4. 切到新启动应用，等待检查结束，读取索引数和目录记录。
5. 切到设置，读取阶段 8 最后保留的明暗、高对比、字号；再验证一次基本导航可继续操作。
6. 核对完成后正常退出。若有未保存日志，保持 NVDA 和语音查看器打开，直到记录存好。

### 记录到文档

1. Alt+Tab 到语音查看器，复制重启后的状态、目录/索引和显示设置的相关朗读。
2. 切回文档替换“【阶段10朗读粘贴处】”；填写重启使用的数据目录、实际恢复结果，记录是否仍有未退出进程等已实际观察的信息。没有检查进程则写未检查，不推断资源释放通过。
3. 保存 Ctrl+S，逐项填写文末汇总表。存在原生选择器、读屏信息或查看器失败时，不能将整场写为全部通过。
4. 将失败登记到 [E 问题与复测记录](E_问题与复测记录.md)，写明版本、最小步骤、实际表现及证据；尚未执行项保持未测。
5. 有实际结果后才更新 [E 验收矩阵](E_验收矩阵.md)的相应子项。此流程没有完整覆盖协作式取消、TXT/图片查看器、真实权限、断网及全部缩放布局，也不代表独立试用或 macOS/VoiceOver 验证。
6. 检查文档已保存后退出 NVDA。重新测试请新建会话记录，保留本场原始结果。

## 证据与范围说明

一份会话记录即可容纳本流程全部阶段，不要求额外拍一整套截图；必要时补清空确认焦点和增量复用等缺少的画面。按真实操作保留证据，不以截图数量代替可访问性判定。

当前已有 macOS/Linux 平台工程与 CI 配置，但该 Windows 流程不能推断其他平台结果。NVDA 语义测试、实际朗读、纯键盘和独立试用分别记账；动态消息只被主动查询读出时，不签收为自动状态播报通过。
