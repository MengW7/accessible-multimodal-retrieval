# Week 5 语料与题集说明

日期 2026-10-28。本文说明新语料、新索引、新题集，以及为什么必须重建。它**不修改** `reports/week3/evidence_set.jsonl`（冻结集，sha256 仍为 `82c080c0…4eb9d6`），也不替换 W4 的任何数字。

## 1. 为什么重建

W4 的 25 条冻结集在 `error_analysis.py` 下暴露了一个结构问题：`ev-01`–`ev-08` 的 `relevantDocumentIds` 同时包含 `sample.pdf` 与 `sample.docx`，而这两份文件**就是当时全部文本语料**（96 块）。金标覆盖整个池子，于是均匀随机抽 5 块的命中率是 **1.0000**。实测 A1 的 `p_doc_vs_chance = 0.7043`——指标无法区分检索器和抛硬币。

空假设由**池子大小与金标粒度**决定，与题数无关：池子仍是 96 块时，题数从 15 加到 100，空假设仍是 1.0。所以第一步必须是扩语料，第二步必须是把金标从「整份文档」换成「具体块」。

关键约定：

1. **每条只有一个金标文档**，`relevantDocumentIds` 长度为 1。多证据题不并入主指标。
2. **金标是块级跨度**，偏移直接在库里查得，不手写：`#page=…;textUnit=utf16CodeUnit;start=…;end=…`。`page=null` 是 TXT/MD/DOCX 的既定约定。
3. **题集生成不加载检索器**。`build_bench.py` 只读 SQLite 和源文件，不调用 `search_probe`，所以生成阶段看不到任何排名。
4. **`verbatim` 的分句必须唯一**：用 `LIKE` 在全库计数，只保留恰好 1 块命中的分句。否则多块都算正确，单文档标签就是错的。
5. **`negative` 是验证过的无答案**：模板里的疑问词（`手机号`/`报价`/`ISO 标准编号`/`随机种子`）在全库 `LIKE` 计数为 0 才收下。不满足就丢弃，不猜。
6. 问句长度上限 110 字符。文本塔预算是 128 token，中文约一字一 token，超限的问句无法编码。

## 5. 口径

`error_analysis.py` 给出文件、块跨度和邻块。heading 问的是整节，块跨度对不上这句问法。`section_scope.py` 在已保存的命中上重算节内正文，不重跑检索。这些列留着解释为什么 heading 停用。当前要报的主指标是 verbatim 的 `span_hit@5`，见第 13 节。

| 口径 | 定义 | 用在哪 |
|---|---|---|
| `section_body_hit@5` | 金标文档的返回块，起点严格落在该节内部 | heading 的停用记录。这样的块与该节重叠，并且不包含标题行起点。第 13 节起不再拿它当要调的数字 |
| `section_hit@5` | 金标文档的返回块与该节重叠，标题行也算 | 对照。dev A1 的 44/77 里，36 条只有标题行 |
| `span_hit@5` | 返回块与金标跨度重叠 | 当前主指标，只报 verbatim |
| `doc_hit@5` | Top-5 里出现金标文件 | 与 W4 的文件口径对照 |
| `bridge_hit@5` | 该块是金标块本身或 `chunkIndex ± 1` | 中间那一块的邻块。snippet 会把邻块拼进去，anchor 偏移不覆盖它 |

这几列并列。不许只报其中较高的一个，也不许把 heading 和 verbatim 合成一个 span。

## 8. 融合归因（本次最重要的发现）

`logs/fusion_attribution_w5.txt`，由 `engine/attribute_fusion.py` 从同一份 jsonl 计算，不重跑检索：

```
both_hit=66  base_only=17  fused_only=6  neither=16
```

**融合是净负的**：17 道题被融合弄丢，只换回 6 道，净 −11。

通道占用（105 题 × 5 位 = 525 个位置）：

```
text_and_keyword = 287  (54.7%)
text_only        = 238  (45.3%)
keyword_only     = 0    (0.0%)
```

`keyword_only = 0` 是权重算出来的。关键词单独第 1 名是 `0.3/61 = 0.004918`，文本第 5 名是 `0.5/65 = 0.007692`，纯关键词行进不了融合前 5。日志第 17 行的 `keyword_can_enter_cut=0` 记的就是这个比较。

同一行被两路都命中时，名次会被改写。文本第 1 名得 `0.5/61 = 0.008197`。文本第 3 名再加关键词第 1 名得 `0.5/63 + 0.3/61 = 0.012857`，加分后越过只被文本命中的第 1 名。净 −11 是这次改序的文件级结果：弄丢 17，找回 6。17 道受损题里，81/85 个位置是 `text_and_keyword` 行。

金标文件要看各臂自己的前 5，见第 11 节：A0 独有 2 题（`w5-012`、`w5-068`），A1 独有 75 题。

## 9. 已知限制

- **自指语料**：全部 23 份文档都在讲本项目，A1 的文件级 0.790 不能外推到本项目以外的文档。
- **当前主指标是段落级 verbatim**：问句摘了金标块里的分句，dev A1 的 `span_hit@5` 是 16/28。字面重叠高。低重叠的「标题问到整节正文」不再写成向量通道已经测过的题。
- **heading 已停用**：54 条 `wrong_span_same_doc` 里 53 条是 heading。问句写进了文件名或小节标题，和标题行重叠高；和金标正文的字面重叠低，A1 heading 里 `wrong_span_same_doc` 的 `lexOverlap` 中位是 0.020（53 题）。含标题行的 `section_hit@5` 是 44/77，其中 36 条只有标题行，34 条那一块的长度不超过标题加 6 个码元。起点落在节内的正文命中是 8/77。去掉文档名之后是 11/60，仍有 43 条停在标题行。小节中位 805 个 UTF-16 码元，文本塔硬上限是 128 token，把 `chunkChars` 调到 400–600 盖不住一节。这些数字留作停用记录，见第 11、12、13 节。
- **无图像题**：Tier 0 语料只有文本，`clipShared` 空间为空。图像检索在本次 benchmark 中未被测量。
- **negative 题未能评估**：检索器没有分数阈值，`search` 永远返回 `topK` 行，所以 `correct_abstain = 0` 是构造性结果，不是测量结果。`topScore` 已逐题记入 jsonl，供以后选阈值时使用。
- **只跑了一次 holdout**：`holdout_scored_runs=1`。`parameters_changed_after_freeze=1`。冻结值是文本 0.5、关键词 0.3、图像 0.2、`k=60`。当前图像权重是 0.49，这一项和冻结值不同；文本、关键词和 `k` 没有改。这个旗标比较的是 `k` 和三个权重，见 `engine/eval_retrieval.py`。
