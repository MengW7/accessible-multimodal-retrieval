# 项目风险管理计划

## 1.风险评级
| 等级 | 含义 | 如何处理 |
| :--- | :--- | :--- |
| 高 | 大概率会碰到，且会卡住核心功能 | 必须有明确的 Plan B 和硬性截止日期 |
| 中 | 可能发生，会耽误时间或降低完成度 | 先按主方案做，可通过报告说明 |
| 低 | 影响有限，或很容易绕开 | 利用边角时间修复，不单独排任务 |

## 2.风险清单
| 编号 | 类型 | 风险 | 可能 | 影响 | 等级 |
| :--- | :--- | :--- | :---: | :---: | :---: |
| R1 | 技术 | BERT / MobileCLIP 转 TFLite 失败，或端侧跑太慢 | 高 | 高 | 高 |
| R2 | 集成 | PDF / DOCX 解析或向量库很难对接到 Flutter 桌面 | 高 | 高 | 高 |
| R3 | 性能 | 大批量文档离线建库导致 UI 假死或 OOM | 高 | 高 | 高 |
| R4 | 质量 | 核心模块单测覆盖率达不到课题目标 | 高 | 高 | 高 |
| R5 | 质量 | 检索不准，演示时搜不到自己刚导入的文件 | 中 | 高 | 中 |
| R6 | 无障碍 | 桌面端读屏 / 键盘操作达不到无障碍 AA 等级 | 中 | 中 | 中 |
| R7 | 环境 | 依赖和数据集太大，环境或磁盘搞不定 | 中 | 中 | 中 |
| R8 | 合规 | 第三方库 License 与开源许可冲突 | 中 | 中 | 中 |
| R9 | 安全 | 调试时把个人文件或密钥提交到 GitHub | 低 | 高 | 低 |

## 3.应对方法
R1　技术　BERT / MobileCLIP 转 TFLite 失败，或端侧跑太慢（高）
- 预防： 第 1 周先用最小探针，找已经能量化的小模型（文本 MiniLM / MobileBERT，图像用更小的 CLIP / MobileCLIP-S0），确认本机 CPU 能对「一段文字 + 一张图」跑出向量。接口先写成统一的 embed()，模型当可替换插件。
- 降级： 换小模型，不改检索流程。切换 INT8 量化、缩小输入长度/图片尺寸、后台线程推理，禁止在 UI 线程跑模型。

R2　集成　PDF / DOCX 解析或向量库很难接到 Flutter 桌面（高）
- 预防： PDF 用现成 Flutter/Dart 插件抽文本；DOCX 用 zip + XML，先不引入完整 Apache Tika。
- 降级： Tika 不做硬依赖。Chroma 嵌不进去就改 SQLite / 本地文件 + 简单近邻检索。解析失败的文件跳过并记下原因，先保证一个操作系统能跑通。

R3　性能　大批量文档离线建库导致 UI 假死或 OOM（高）
- 预防： 建库做成可取消的后台任务（Isolate / 原生线程），UI 只显示进度。增量索引：已处理过的文件不重复嵌入。限制单次批大小，大文件按页/按块切。
- 降级： 默认先索引文件名、路径和前几页，全文放到空闲再补。单文件过大就跳过正文、只保留元数据。OOM就降批大小或换更小模型。

R4　质量　核心模块单测覆盖率达不到课题目标（高）
- 预防： 从解析、嵌入、检索这些纯逻辑层开始写测。FFI、模型推理、文件对话框用接口包一层，测试打 Mock，不要直接测原生库。每周开发的同时注意覆盖率。
- 降级： 保证「能单测的核心逻辑」尽量高；UI 和原生用少量关键路径集成测试。

R5　质量　检索不准，演示时搜不到刚导入的文件（中）
- 预防： 必须做「关键词 + 向量」混合：文件名、路径、扩展名至少要能命中。
- 降级： 扫描件/截图先走图像向量，有时间再加可选 OCR。

R6　无障碍　桌面端读屏 / 键盘达不到 AA（中）
- 预防： 第一版 UI 就加 Semantics、焦点顺序、对比度。先完成键盘的完整流程：打开库 → 输入查询 → 看结果 → 打开文件。
- 降级： 次要设置页后补。文档中写哪个系统、用哪个读屏测过。

R7　环境　依赖和数据集太大，环境或磁盘搞不定（中）
- 预防： 不下载完整 NQ / COCO / Wikipedia。只要小样本：几十到几百条文本、几十张图、几份 PDF/DOCX。Flutter 桌面先在自己日常用的那台电脑跑通，版本写进 README。
- 降级： 官方包下不动就换更小的数据集，报告里注明来源和抽样方式。

R8　合规　第三方库 License 与开源许可冲突（中）
- 预防： 第 1 周列一张表：依赖名、版本、许可证、是否打进发布包。
- 降级： 许可不允许再分发的库/权重立刻替换。发布包只带许可兼容的第三方库。

R9　安全　调试时把个人文件、环境或密钥提交到 GitHub（低）
- 预防： .gitignore 排除真实文档、索引数据、.env、密钥、模型权重。默认不联网，日志不写入文件正文。提交前查看 git status。
- 降级： 误提交后立刻从仓库处理掉，密钥作废换新。
